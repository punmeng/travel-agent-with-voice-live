# 梅好旅程語音示範講稿（約 5–8 分鐘）

## 示範前一分鐘

本機版本狀態與限制見[版本交接](CURRENT-VERSION.md)。目前只示範本機服務；不要把Hosted Agent原型、demo-key登入或Azure線上發布說成已完成。Voice Live標題旁的小標籤顯示真正後端角色與完成／等待狀態，不是第五個agent。

開啟 http://127.0.0.1:3100 ，確認標籤為「AI live · 旅遊／付款模擬」。使用新版 Edge／Chrome 與耳機，確認已啟動後端、Azure CLI 身分仍有效，`.env` 為 foundry 且 Voice Live 已啟用。不要在公開畫面顯示 `.env`／token。

每則助理回覆最多50詞，較長內容會提示「說『繼續』看下一段」。逐段說「繼續」直到完整行程／航班／確認價呈現；不要在尚未讀到完整金額與條件時確認。五天行程不會縮成三天，只是分段。想選第二班，先讀完第二個候選；演示時間不足可只比較第一個已讀完整候選。

**先核對資料日期範圍與今天日期。** 現有合成航班涵蓋 2026-10-16 至 2027-02-12。下述日期只適用於 2026-10-16 這次驗收，示範時請換成範圍內、尚未過去的出發與回程日期，兩端都必須有資料。若示範日期已超出範圍，先更新生成來源並重新生成，且經核准同步更新知識快照；不要把過期固定日期當可售機票。

文字與語音共用100個成功完成的使用者回合（含「繼續」），已移除應用五分鐘截斷；每旅程三次連線，供應商／網路仍可能斷線。等待超過15秒，畫面顯示「我還在查詢，請稍等一下。」；此提示不是新回合，也不另行朗讀。每一步只回答自然提出的相關問題。

## 0:00–0:45｜開場與真正收音

講者：「這是非官方梅好 Airlines風格概念示範。AI 使用真正 GPT-5.4 與 Azure Voice Live；所有航班、機位、票價和結帳均為合成，不會扣款、訂位或開票。」

按 **Talk to agent → 開始語音**，允許此網站麥克風。等「聆聽中」再說話。不要提供護照、姓名或信用卡資料。若首次無聲，先確認裝置音量與麥克風選擇；不要把合成測試結果說成真人裝置驗收。

## 0:45–2:15｜自然靈感與五天行程

旅客說：「我想去日本玩幾天。」

預期：語音轉錄出現在聊天，意圖協調師自然詢問興趣／天數或日本區域，**不要求機場代碼、完整日期、人數或艙等，也不搜尋機票**。

接著說：「想賞楓，不要走太多路，五天，帶媽媽。」

預期：保留日本、賞楓、少步行、五天與媽媽同行，不直接推定成人數或媽媽年齡。若詢問城市，可接：

「那東京好了，幫我安排五天。」

預期：旅遊規劃師給五天行程與休息安排，不強迫先選機場／日期。交通時間、營業與無障礙資訊未核驗，要明確保留限制；賞楓現況也不是即時資訊。文字可見知識引用，朗讀的是相同後端主回答。

講者：「四角色由後端協調：意圖理解、行程規劃、航班查詢、票價與購買。靜態知識是完整合成資料快照；真正用於選班與報價的是同源工具，不是把RAG文字當價格。」

## 2:15–3:30｜逐步找來回票

旅客說：「想從台北出發，幫我看看機票。」

若助理詢問台北機場，回答：「都可以。」預期保留台北並接受桃園／松山，不重問出發城市。東京機場也可回答「成田或羽田都可以」；只有符合DEMO假設示範的路線才列結果，缺松山／羽田不會塞入其他航空。不需要說IATA代碼。

再按助理問題提供日期、人數與艙等。這次驗收可說：

「2026年11月12日出發，2026年11月16日回程，我們兩位成人，經濟艙，早去晚回，幫我找機票。」

**實際示範必須按示範當天更新上句日期。** 不要只說「下個月中」然後要求系統猜一天。若先前已說過人數／機場／日期，不應重問；若仍模糊，助理只問下一個必要問題。

預期：航班查詢師用編號文字列出真實生成的去程與回程合成航段、各地時間／時區、兩人來回TWD含合成稅費總額與候選價期限。早去晚回是排序偏好，不保證庫存；沒有符合艙等或日期會明確說沒有，不虛構。

時間充裕可說：「也比較前後一天。」每組已接受機場配對只搜三組成對平移日期；最多2×2機場配對，平行2，共用60工具單位，不是無界展開。比較會更新候選清單，後續以新編號為準。也可問「介紹台北到東京的合成航班時刻資料」，這會直接檢索靜態航班知識，不先填購票條件。

## 3:30–5:00｜選班、確認價與模擬連結

先讀目前編號清單，再說：「選第二班。」

若只有一個候選則改說「選第一班」。預期：票價代理確認選擇，尚未下單。

說：「幫我看看現在這個票價，準備結帳。」

預期：後端重新報價，清楚顯示最新總額、TWD、版本與期限；若價變會顯示原價→新價，舊同意失效。

**等完整報價出現在對話中，核對金額、行程與期限後**才說：

「我同意這個報價，請給我模擬結帳連結。」

預期：只接受剛顯示的最新報價context，建立同session的限時連結。不應只說「好」「同意」或「便宜一點才同意」；此類含糊／附帶條件不會購買。

按 **停止語音** 後，點對話中的「開啟模擬結帳（不收款）」。落地頁顯示相同來回行程與確切金額，**沒有卡號欄位、不扣款、不訂位、不開票**。這不是泛用航空公司首頁，也不是所選真實機票的付款連結。返回旅行對話。

## 5:00–6:30｜聲音與文字共用上下文

按停止語音，再用文字輸入：「改成三個人，先不要買。」沒有五分鐘應用截斷，不需要為此搶時間。

預期：更新旅程並使舊候選、報價／同意／結帳失效，不真的購買。再開始語音說：「我們還是希望不要走太多路。」

預期：前面聊過的城市、媽媽、天數與步調仍在同旅程，不重開另一個泛用聊天機器人。按靜音可暫停麥克風；按停止會關掉音軌與連線。思考中說「不是十月，是十一月中」，應保留城市、標示舊轉錄已被更正，只交付最新答案；朗讀中插話應清舊播放。原本確認／重報價等交易會先安全完成，不宣稱可以取消已完成動作。房間回音／各裝置效果須現場驗證，建議耳機。

日期與工作流重現：先說「台北到大阪的飛機，來回十一月中」，機場回答「都可以」，再說「十一月十五號出發，十一月二十號回來，兩人，預設經濟艙，給我時間先」。應按當年或已明說年份保留日期、自動顯示去回合成時間；不要求再次輸入搜尋命令。展示時先確認這些日期仍在資料範圍且未過期，若否就選範圍內未來日期；不能讓模型自動替換年份。

結語：「目前證明的是自然規劃、可追溯合成知識、受控票價工具，以及安全模擬結帳。正式販售仍需航空庫存與付款供應商、登入、持久化、正式交易／退款狀態與上線治理。」

## 最小故障處理

| 狀況 | 處理與對觀眾說明 |
|---|---|
| 麥克風被拒絕 | 在瀏覽器網站權限允許麥克風後重新開始；否則停止後改用文字，明說未完成現場語音驗收。 |
| Azure 連線或權限錯誤 | 顯示的錯誤碼／關聯識別碼交給後端排查，停止後用文字接續；若Foundry也失敗，不假裝仍是live成功。 |
| 語音辨識有誤 | 停止後用文字澄清，或重新開始自然更正；任何價格／選班／確認都核對畫面，不依錯誤轉錄成交。 |
| 100完成回合／三次連線上限 | 沒有應用五分鐘截斷；達旅程回合上限或三次連線用盡時明說限制，再決定開新旅程（會清原狀態）。 |
| 上一段仍在處理 | 等原文字回合完成，開始語音按鈕會恢復；不要連點或取消有效交易。錯誤code／關聯ID在語音「診斷資訊」中。 |
| 無候選或報價過期 | 自然調整日期／艙等或重新報價；不偷偷改艙、不保留過期同意，不用舊連結假成功。 |
